## Race & block
- X Millas Costa Blanca, l'Alfàs del Pi. **Sun 2027-04-18**. 10 mi road, +225 m. Same course every year.
- Block: W1 = Mon **2026-12-07** (ISO 2026-W50) → W19 = race week (2027-W15). Phases: Rebuild W1–4, Base W5–8, Build W9–16, Sharpen W17, Taper W18, Race W19. Recovery + benchmark-climb retest every 4th week.
- **No goal time.** Owner: tissue leads, never chase. Plan distances are **ceilings**, not quotas.
- Main target: fading on climbs. Data says the fade is **late** (finish drag vs mid-race climb), not climbs per se — see `data/refs/editions.json`.
- Strava units: imperial → site defaults to mi (toggle km). Storage is metric.

## Invariants
1. Main thread orchestrates; agents/scripts do the work. Running deterministic scripts counts as orchestration.
2. One-way data: raw → summary → site. Builder never reads Strava; analyst never writes HTML.
3. Vice palette only in `site/` (table below). Gate C check-3.
3a. Relative URLs only (`./x.js`, never `/x.js`). Gate C check-2.
3b. `site/app.js` is source; pages load generated `app.min.js` (`scripts/build/minify.mjs`). Gate C check-8.
3c. `site/data.js` (`window.XM_DATA`) is the **only** data the site reads, generated by `scripts/build/inline-data.mjs`. Gate C check-4 deep-compares it to `data/`.
4. Dates Europe/London; week = Mon 00:00 → Sun 23:59:59. Files named by ISO week.
5. `data/plan.json` hand-maintained; agents read-only.
6. No secrets in repo. Strava via MCP.
7. Each pipeline run = one conventional commit (`refresh: 2026-W50 (mid-week)`, `report: 2026-W50`) + push.

- On-foot types: Run, TrailRun, VirtualRun, Hike. Walk excluded, never flagged.
- Injury watch: `calf` (precaution) + generic body parts under `injury`. Edit `WATCHES` in `scripts/build/summary.mjs`.
- No python/jq on this machine: Node only (gates via bash wrappers).

## Data shapes
`data/plan.json`: `race`, `week1_start`, `targets_are: "ceilings"`, `benchmark_climb {name, strava_segment_id, note}`, `races []`, `every_week [{w, t}]`, `weeks [{week, iso_week, start, phase, dist_target_km, notes?, focus, key [{w, t}]}]`. `w` = workout id, `t` = session text.

`data/workouts.json` (hand-maintained): `course_facts`, `workouts [{id, name, kind, what, why, for_xmillas, how, watch_out, evidence: strong|moderate|consensus|your-data, sources [{label, url}]}]`. Plan site shows a ? popover per session plus a library. `inline-data.mjs` fails the build on an unknown `w`.

`data/raw/YYYY-Www.json` (data-agent only, unfiltered): same as gtcb —
`{iso_week, training_week, window {start, end, tz}, fetched_at, activities [{id, name, sport_type, start_date_local, distance_m, moving_time_s, elapsed_time_s, elevation_gain_m, description}]}`.

`data/summary/YYYY-Www.json` (`scripts/build/summary.mjs`):
```json
{ "iso_week": "", "training_week": 1, "phase": "", "generated_at": "", "window": {}, "days_elapsed": 1,
  "distance": { "actual_m": 0, "target_m": 0, "prorated_target_m": 0, "pct_of_target": 0, "pct_of_prorated": 0, "long_run_m": 0 },
  "time_on_feet": { "actual_s": 0 }, "vert": { "actual_m": 0 },
  "sessions": { "count": 0, "on_foot_count": 0 },
  "daily": [{ "date": "", "vert_m": 0, "time_s": 0, "distance_m": 0 }],
  "flags": [{ "type": "calf|injury|over_ceiling|long_run_spike", "detail": "" }] }
```
+ `data/summary/index.json` `{weeks: []}`.

`long_run_spike`: a run >10% longer than the longest on-foot run in the previous 30 days (Frandsen/Nielsen 2025, BJSM). History = other raw weeks + optional `data/refs/preblock.json` (`{activities: [...]}`, raw activity shape). Before W1, data-agent should write the 30 days before 2026-12-07 there.

`data/reports/YYYY-Www.json`: prose only — `{iso_week, training_week, generated_at, headline, narrative[]}` + index. Same as gtcb.

Refs (regenerate only when inputs change):
| File | From | Script |
|---|---|---|
| `data/refs/editions/<year>.json` | Strava streams, 5 editions 2022–2026 | `scripts/import-streams.mjs` |
| `data/refs/course.json` | 2026 edition track; hand-set sections | `scripts/build/course-data.mjs` |
| `data/refs/pace-model.json` | 2022/2023/2026 (continuous runs) | `scripts/build/fit-grade-curve.mjs` |
| `data/refs/editions.json` | course + editions; Minetti GAP | `scripts/build/editions.mjs` |

## Pipeline
**Routine refresh:** `data-agent` (haiku) fetches the week → `node scripts/refresh.mjs [week]` (Gate A → summary → Gate B → inline-data → minify → Gate C) → commit + push. Gate C check-6 needs a tree where only `site/` + `data/` changed: commit dev work first.

**Weekly report (on demand, completed weeks):** data-agent → `refresh.mjs <week>` → `report-agent` (Gate R on stop) → `node scripts/report.mjs <week>` → commit `report: <week>` + push.

**Full chain (site code changes):** data → analyst → builder → reviewer, each verified by Gate A/B/C/D via `SubagentStop` hooks (`.claude/settings.json`). Reviewer invariant ids closed set: `1, 2, 3, 3a, 4, 5, 6, 7`.

Pre-block (no raw files yet) gates A/B/R pass with "nothing to validate".
